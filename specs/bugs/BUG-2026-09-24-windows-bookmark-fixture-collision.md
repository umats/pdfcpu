# Windows CI: bookmark test output collides with shared fixture

PR #1, [Test run 36028223392](https://github.com/umats/pdfcpu/actions/runs/36028223392), failed only on Windows Go 1.26: `TestAddSimpleBookmarks` could not replace `pkg/samples/bookmarks/bookmarkSimple.pdf` (`Access is denied`). The test writes to a tracked fixture that other package tests read. `go test ./...` runs packages concurrently; Windows can reject replacement while the file is open. The staged-write production path remains correct and must not be weakened.

First fix: write this test's output under `t.TempDir()`, retaining PDF validation. Focused and full local preflight passed, and the push run passed Windows Go 1.26. But the simultaneous [PR run 36030743909](https://github.com/umats/pdfcpu/actions/runs/36030743909) failed on another shared tracked fixture, `samples/create/primitives/textAndAlignment.pdf`. This confirms the package-level fixture collision is broader than one test. Serialize non-Linux test packages with `go test -p 1` until the shared outputs are isolated. Windows CI verification remains pending; do not merge while CI is red.
